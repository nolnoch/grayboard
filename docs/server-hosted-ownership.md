# Hosted ownership

```doc-meta
owns: hosted admission, ownership history and live source-session rows, grant attachment, the BindGate, live-session bounds
invariants: a hosted root's session ID is stable and never ends (its ownership does), a hosted child's ends at its release, and a session that holds an alias always has an unended `ids` row
code-pointers: src/server/hosted.ts, src/server/hosted-types.ts, src/server/store/hosted.ts, src/server/db.ts, src/core/session_end.ts
companions: server-hosted-mcp.md (the endpoint), server-sessions.md (bind)
```

Hosted admission charges a separate per-user request bucket after OAuth authentication but before source-session or alias lookup, not the bind limiter (`server-rate-limits.md`, #189, #226). Request-local application contexts resolve stable grant-client source sessions; charging each request against the bind limiter's budget would let ordinary fleet tool traffic starve binds. Delivery upkeep (role=subscriber: lease renews, inbox reads, receipts) is charged to a second per-user bucket chosen at admission from the role (`admitHosted`, `src/server/application.ts`), so one user's delivery fan-out can't throttle that user's tool calls (#845); exempting it instead would leave an unmetered write path, since every renew writes the session row. Each bucket keeps its own refusal streak, audited `hosted.rate_limited`/`hosted.rate_limit_ended` with `bucket: native|subscriber`. The hosted defaults support sustained fleet requests with bounded burst headroom. Defaults: `src/server/rate_limit.ts`; overrides: `src/server/config.ts`. A refusal is a typed MCP error with HTTP 429 and Retry-After, never dispatches the tool, and recovers after refill; arbitrary application or storage errors never become throttles. Request-local refusal state stays with its exchange, including concurrent refreshed legacy requests. Hosted and bind refusal audit streaks remain independent, as do live-state quotas.

A request whose client aborted while it waited (a `RequestAbortedError`: the write queue skipped its body, or `select` saw the abort) is not a failure: it logs `hosted MCP client aborted` at warn with `category: "client_aborted"`, the same provenance fields and no `hosted MCP failed` line (#1535). A request the server cut is neither: one the closing endpoint refused (`RequestClosedError`), or a `RequestAbortedError` once the app is stopping, logs `hosted MCP request cut by server` at warn with `category: "server_cut"` (#1541). The check is `stopping`, not `closed`: `app.stop()` cuts every connection before it closes hosted MCP, so a waiting request's signal fires while the endpoint still reads open. A call the close cut after dispatch stays `hosted MCP failed` (`EndpointClosedError`, answered 503): its write may have committed (#1342). A handler that hasn't answered within its deadline is cut by the server too, before the listener's idle timeout (`IDLE_TIMEOUT_S`, 75 s) would cut it as a client abort: the deadline (70 s) starts once the body is read and ends once the response starts, so a slow upload or a long stream never meets it. Its line is `server_cut` with `cut: "deadline"`, and the call is answered 503 since its write may have committed (#1591). Unexpected-failure diagnostics use code-owned catch-site provenance and bounded exchange context, never exception messages, stacks, causes or arbitrary properties (`src/server/diagnostics.ts`, #386). From the error they take only its class, a SQLite-, errno- or Bun.SQL-shaped `code` (or, on `S3Error`/`S3StoreError` alone, S3's error code such as `InternalError`, #1608) and a five-character `sqlstate` (Bun.SQL's string `errno`), each matched against a bounded pattern and read as data descriptors so no getter or `toString` runs. Root throwing locations are deliberately unavailable: even plausible source frames can contain credentials. SDK error callbacks and surrounding catches share exchange-local deduplication; clients get generic unexpected-error text, while factory authentication loss remains HTTP 401. The Slack bridge follows the same provenance and generic-reply boundary.

Durable hosted ownership history is separate from live source-session rows (`src/server/hosted-types.ts`, `Repo.hosted`). A hosted session holds several names (#451): `bind` and `unbind` (`src/server/hosted.ts`) run `application.bindNow` and `application.unbind` on a session rebuilt from the root's holds (`hostedSession`), inside the root's one transaction; they preserve ownership, children, status and claims (claims stay with their address, `handles.md` §1); a bind that adds a hold or an unbind that releases one bumps the generation and closes delivery. A refused bind's `refused` binding row is written after the transaction rolls back (the session's `afterRollback`). Every hosted path that runs in a transaction a refusal's throw rolls back (the gate's row selection, `run`, `owning`, `transfer`, `session_register`) collects such rows the same way (`refusalRows`, #467) and writes them once it has unwound; one whose write fails is a `hosted.refusal_row` failure diagnostic and counted (`refusalRowsLost`), and the caller still gets the refusal. The last `unbind`, or a revocation of the last hold, clears the lease deadline: the root is unbound but owning, and the sweep leaves it to the idle window. A revocation releases only the revoked hold, through the hosted store's transaction so the lease closes at once. HTTP has no frame, so that transaction keeps the loss (`hosted_alias_lost`, #453) for two readers. The agent's reader takes it once: the root's next native `whoami` (as `alias_lost`) or tool result, a refusal included, appends the plugin's notice (`aliasLostNotice`, `src/core/bindings.ts`; audited `hosted.alias_lost_notified`) and marks the result with `_meta["io.github.nolnoch.grayboard/alias_lost"]` (`GRAYBOARD_ALIAS_LOST_META`, `src/shared/session_meta.ts`), on which the adapter's proxy drops its cached instructions. The Controller's reader is reported, not taken: every subscriber `whoami` carries `alias_lost` until the root's next `delivery_open` takes the reported entries (audited `hosted.alias_lost_seen`), so a resume or a reopen that lost a `whoami` answer still learns it; the Controller drops those holds from what it rebinds, keeps receiving under the rest instead of pausing and shows the loss on its status line, and a `delivery_open` refused because the primary went between its `whoami` and the open retries once. A `bind` of the lost alias clears both readers' entries for it. A child's calls take none (pi probes a child with `whoami`), nor do `bind` and `unbind` results; an ownership end drops it. Old-name DMs never move; a DM to the root's own ID is pushed without an address, and an alias DM carries its address, which the client checks against its holds. A bind refuses a name any other session holds with `alias_held` naming the holder; a contending hosted root whose lease deadline has passed, or that was never leased and is idle past the window, is ended instead. Child registration is depth one, under ordered root/child writer gates and one immediate transaction; a child uses its root's effective name, cannot bind or control delivery, and can end only itself. Root end removes descendants atomically. A child idle past the window (no request of its own, and no `session_register` of it) is parked by the sweep (`hosted_sessions.parked_at`, audited `hosted.child_parked` against the root, #566): `Repo.hosted.all(r)` leaves parked rows out, so they count against neither the root's `MAX_CHILDREN` nor the user's and global rows, while `get` and `children` still see them. Its next request, or its root's `session_register` of it, makes it active again under the root's current grant (`unpark`, audited `hosted.child_unparked`), admitted against the same limits as a registration; a refusal leaves it parked. A refused registration, convert or unpark for the root's child limit says local mode's `childCapacity` text (#584). A root keeps at most `MAX_CHILDREN` parked children: past that, the sweep that parked them releases the oldest parked (by `parked_at`, then last activity, then ID) in the same transaction, audited `hosted.child_released` with `reason: "evicted"`; an evicted child that calls again starts as a root, as an ended one does. A child's release (its `session_end`, an eviction, its root's end) ends the child's `ids` row through `endSession` in the release's transaction, with that reason (`closed`, `evicted`, or the root's end reason); the store queues the ends' wakes and the application runs them and the bounces after commit (`takeEnded`, #475 item 1). An ID whose row ended that comes back (an evicted or closed child, a row an earlier start ended `wss_removed`) gets the row reopened by `hostedRegister`: `ended_at` and `held_aliases_json` cleared, audited `id.reopened` with the old `ended_at` (#475 item 7a). A hosted ID is the harness's own and can't change, so refusing it would lock the session out; and revocation (`aliasUses`), identity deletion (`aliasUser`) and retention read only unended rows, so a holder on an ended row would escape all three. No idle check ends or parks a session with a call running (#584): the server counts in-flight calls per session ID in memory, a child's call counting for its root too (ending a root deletes its children), and the sweep's root end and child park and `bind`'s idle-contender end all skip a counted row (the bind probe needs no skip: it runs alone on the root's gate, after the root's calls drain); lease expiry and a disabled user still end it. A call's end touches the row and its root again, if both are still as the call found them, so the idle window runs from the call's end. A call's touches coalesce (#912): each skips a row whose `last_seen_at` is within 5 s of now, or a tenth of the idle window if that's shorter, so the idle clock and the eviction order's last activity resolve to that window (a native tool call otherwise wrote each row up to three times: its exchange's selection, its own gate and its end); a `session_register` of an already-registered child still always touches the child. Neither an exchange's selection (`snapshot`, which every MCP request runs before its tool) nor its `session_end` unparks it, so ending one is never refused for capacity, and a resource read leaves it parked. Why server-side: pi and omp cache a child's registration, so a deleted row's next call would start an ownership of its own (#523). Children take no restart credit (#423): they hold nothing, and an outage past the window parks them all, each unparked on its return. Registration is server audit, not a fabricated name-binding event. Hosted source IDs register an `ids` row against the authenticated principal (`hostedRegister`; another principal's row is `id_collision`, its `id.collision` audit row written after the refusal's rollback, from a session start and `session_register` alike, #1077) without claiming a reusable session-key proof; its harness fact is `harnessFor` (`src/server/oauth-config.ts`): `opencode` for OpenCode's client, a built-in's own label, else the opted-in client's exact ID, which `peer_list` shows and `match.harness` filters. A child attributes writes to its own ID while sharing the root's mailbox. Alias holds follow durable ownership and rebuild before requests after restart; releasing ownership drops the hold (`released`, detail the end reason), not the source ID's history: a root's source ID is stable, so it never ends through `endSession` (`disconnectUser` skips hosted-owned IDs), and its mail isn't bounced nor its claims released. ID status stays with that source across bind and unbind, while a mailbox's queue opt-out stays with the alias.

Only successful bind, delivery open or root registration moves the ownership's grant attachment. Ordinary same-account/client writes under another grant are audited without attaching it. Attached-family revocation and disable end the ownership, descendants and name binding atomically; post-commit invalidation closes memory state. That invalidation is per row (#399): each `Repo.hosted` write that changes a row (insert, update, end, park, unpark, a child's end) names it to the observers after commit, with the row as the commit left it (#807 P3 A7h2), so the holder rebuild, delivery's lease check and the hosted MCP streams judge that row in the commit's flush, before another request; a `touch` (`last_seen_at` only) tells nothing. A grant or user change tells `null`, and a named commit whose facts read failed carries no row: both request a full pass, which reads every watched row on its own transaction and judges them in its apply, after any bodies already queued, so a lease or stream ends there rather than in the flush (a pull meanwhile reads its own row and is refused). The pass reads the watched rows before its holder rebuilds, each rebuild in its own savepoint, so a rebuild that fails can't hold a revocation back. The sweep runs off the request path: a request settles only its own row and its root under the sweep's rules (`settle`; `withGate`'s skips the disabled check for the user the request just authorized: `activeAccess` refuses a disabled user, and `setDisabled` ends that user's rows in the transaction that disables them, #881; that check runs outside the transaction and awaits, so the body checks again in the transaction unless `Repo.commitGeneration()`, read before the check, is unchanged when the body starts, #807 P3 A7d2b; a native tool call's own gate settles nothing the exchange's just did: `run` reuses the exchange's verdict (`withPrior`, #907) while the row and its root still read as that selection left them (same ownership, root and generation, unparked, lease live, neither idle) and runs the full gate on any difference), and a 250 ms timer ends lapsed leases through `idx_hosted_deadline`, with the idle, park and disabled passes every 5 s and a full holder reconcile every 30 s as the backstop. So another session's lapse shows up in presence and capacity counts up to one tick late; a capacity refusal (`admit`, `admitChild`) runs the sweep, at most once per tick and never ending the caller's own rows, and counts again before refusing. A lease's durable deadline survives disconnect and restart: timely reopen retains ownership and status, while expiry releases exactly once without needing a contender. Never-leased owners use the contender-only idle rule. Server shutdown drops memory delivery but leaves durable deadlines, auditing each dropped capability as `hosted.lease_detached`; it is not explicit session end. Lease and idle clocks stop while the server is down (#423, `creditDowntime` in `src/server/hosted.ts`): start credits the gap since the last heartbeat to each root's live lease deadline or not-yet-idle clock, except a disabled user's. A lease deadline is capped at one TTL past now and an idle clock at now, so a stale heartbeat (a rollback to a release without it, or failing heartbeat writes while renewals succeed) can't let a dead owner hold its name longer. A gap within two heartbeats is indistinguishable from a live server or a concurrent opener and earns nothing; the credit commits with the new heartbeat, so it applies once. Each change is audited as `hosted.lease_restart_credit`, and every start, credited or not, as actorless `server.started`.

Tools, byte transfers, pending reads and receipts take the effective root's BindGate reader; bind, registration, end, grant attachment, delivery open and release take its writer; delivery renew takes the reader. Gates retire only after active and queued callers finish. Cross-process writers require more than a process-local gate: native effects reselect authority and exact root generation/name/child relation inside their effect transaction; receipt authority, issued-prefix validation and cursor updates share one immediate transaction. Database state commits before holder publication, without an intervening await. Native effects and audits stay inside that transaction; live DM/board payloads, observer invalidations and wakeups wait for its outermost successful commit (`src/core/sqlite.ts:afterCommit`). Nested savepoint success only transfers effects to the parent; rollback discards them. Use `db.transaction`, not raw SQL transaction boundaries. Postcommit sink failure cannot fail or roll back the durable operation, and failed board publication leaves no phantom inflight receipt. Lease capabilities and issued batches capture ownership, generation, grant and name; stale receipt, renewal, release or delayed cleanup cannot mutate a successor or advance its cursors. A canceled open cleans up only unaccepted state created by that attempt; successful reuse fences older cleanup and preserves existing notification hooks. Receipts acknowledge durable host admission only, not DM handling. `dm_ack` remains separate.

Live-session admission is bounded transactionally per account, globally and per root (`src/server/hosted.ts`), including unbound contexts and restart-restored rows. Refusal cannot attach a new grant. Unbound idle roots and their descendants retire without a contender; bound never-leased ownership keeps its contender-only rule. These are live-state limits, not an audit-retention policy.
