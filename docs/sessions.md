# Session lifecycle

```doc-meta
owns: a session's life in local mode and both modes' shared records: name acquisition, mixed versions, session end, keyed sessions, binding events, conversation-following names, retained local children, session titles
invariants: an ended session leaves nothing deliverable against its ID, and a send to it fails rather than vanishing; session end is one transaction; a Claude Code title names an effective hold, never a configured fallback
code-pointers: src/core/session_end.ts, src/core/session_id.ts, src/core/schema.ts, src/local/binding.ts, src/shared/session_meta.ts, src/shared/claude_agents.ts, src/shared/claude_identity.ts
companions: handles.md (names and binding), child-sessions.md, server-sessions.md (the server's side)
```

- **Local acquisition** (`src/local/binding.ts`): every session (delivery owner, tools-only process, `tail`) writes a `bindings` row at start (`name` NULL while unbound) with its pid, start time and harness pid (its harness and cwd are its `ids` row's), audited `id.registered` (detail fields: `src/local/binding.ts`, the server's `delivery` and `keyed` plus harness rule and pids); `pid`/`proc_start` are always the process whose death ends the session (keyed sessions: the harness, below). Acquire runs in one `BEGIN IMMEDIATE` transaction: a row holding the name whose pid is alive with a matching start time holds it; a dead holder's row is cleared. The hold commits with the alias's `last_seen`, so from that moment a `dm_send` to the name queues instead of failing as never connected, before the holder listens. Liveness is `kill(pid, 0)` plus the start time, never a socket probe, so the write lock isn't held across one, and a holder whose event loop is blocked keeps its name (#80: probe → unlink → listen let two starters both win). Dead only on evidence (`src/shared/proc.ts`): a zombie or exiting process (state `Z`, or `X` on Linux) is gone though `kill(pid, 0)` succeeds (#331); an unknown start time on either side (no recorded value, `ps` failed) counts as alive, logged once per pid, because a reused pid holding a dead name is safer than reaping a live session. Only the row owner listens: on a temp path renamed onto `sock.<name>`, unlinking on stop only if the inode is still its own, because Bun's `server.stop()` unlinks its path unconditionally and would delete a successor's socket. The stat → unlink check isn't atomic; the window is microseconds wide and needs a successor's rename to land inside it. A flagless Claude Code session (#71) holds its name without listening: offline to peers, DMs wait.
- **Mixed versions.** A pre-#182 session holds a socket and no row, so when no live row holds the name the acquirer probes `sock.<name>` before the transaction (a dead row doesn't skip the probe): live socket, no live row → held. When no row (dead or alive) holds the name and its last `binding_events` row is a release, that socket is a 1.x session that has just rebound off it and not yet closed it: the refusal says to retry in a moment, and `dm_send` to the name reports `delivered_now: false` (`lastWasRelease`, `src/core/bindings.ts`). Known limit: a pre-#182 session *starting* concurrently can still unlink the new owner's socket; closed once both run new code. A post-#182, pre-#284 process holds by `bindings.name` alone: HEAD counts a live row naming the alias as its holder (`holdingSession`), and a HEAD acquire writes `bindings.name` too, so the 1.x check sees it. `bindings.name` is `UNIQUE`, so it mirrors the primary only (moved to the next hold, or `NULL`, when the primary is unbound): a 1.x process sees a HEAD session's other holds only as live sockets. A 1.x reap deletes a dead HEAD session's `bindings` row but not its other rows, so an unended local `ids` row with no `bindings` row counts as dead and the next opener ends it (below). Releases v2.0.0 to v2.3.1 know no child sessions and run that sweep on every open over every unended ID, so a local child with no `bindings` row would be ended while its root lives, and its stable ID refused `id_ended` from the root's next keyed restart on (#539). Its copy of the root's liveness row (`child-sessions.md` §Local children) keeps it out of their sweep; those releases judge it alive exactly while its root's row is, leave it out of their live sessions as they do any `delivery = 'none'` ID (no `unbound_sessions` row, no CLI shell identity; `bindings.name` stays `NULL`, so it holds nothing), and reap it with its root when the root's process dies. `tests/integration/ids.test.ts` runs v2.3.1 (the sweep is unchanged since v2.0.0) beside a HEAD root and its child through a keyed restart.
- **Session end** (`endSession`, `src/core/session_end.ts`; #284 decisions 4 and 10): one transaction that leaves nothing deliverable against the ID. It marks `ids.ended_at` and `held_aliases_json`, bounces the ID's unread direct mail to each sender, one bounce per sender (`messages.kind = 'bounce'`, threaded under its latest unread message, listing the others' ids and naming what it held; dropped, and counted `unbounced`, when the sender is an ID that has ended or whose row retention pruned) (#334), releases its claims (lapsed ones through the sweep first, so they end as lapses; queue posts redelivered, watchers told; a release the core refuses (`CoreError`) still deletes the claim, unannounced, since a claim on an ID that can't act would never free), drops every other row keyed by the ID (`forgetHandle`, the mail port's `dropReader`, unbound uploads), releases its holds (`released`, detail `session_end`) and ends its live child sessions (`ids.root_id`; each through `endSession` with `why` naming the root, since a child acts only under its root's addresses), audited `id.ended` (detail fields: `session_end.ts`, a root's row listing its `children`; a local row names the ending process (`by_pid`), and a reap's adds the dead row it judged and whether it was probed again inside the lock (`reaped`, #330); the server's row goes to its access log through an `AuditSink`). Alias claims and mail stay: the alias is durable. Mail per mode goes through a `MailPort` (local `src/local/mailbox.ts`, server `Repo.mailOn(tx)`). On a server only a session the removed WSS transport left ends here, once at start (`why: wss_removed`, `server-sessions.md`); a hosted root's ID never ends here, and a released hosted child's ends in its release's transaction (`handles.md` §Hosted owner). Locally a clean exit ends the session, and **every opener** (`openLocalDb`, `src/local/open.ts`) ends dead ones, as do `peer_list` and the candidate list (`liveSessions`) and a bind that finds a dead holder (judged and cleared inside the acquire's own transaction). `peer_list` never waits for the write lock: while another process holds it, its ends are skipped at once, unlogged, and the dead stay out of its list until a later `peer_list`, opener, candidate list or bind ends them (`liveSessions(db, { wait: false })`, busy timeout 0, #894). The openers', `peer_list`'s and the candidate list's candidates are judged dead outside the lock, then each is re-read and ended in its own `BEGIN IMMEDIATE`, probed again only if its pid or start time changed, so an unchanged dead row costs no start-time read under the write lock (`reap`, `src/local/binding.ts`; the audit's `reaped.probe` is `pre_lock` or `re_probed`, and a bind's reap records `pre_lock` too, #335): one that throws is logged and audited `id.end_failed` (`error`, `by_pid`) and leaves the others ended and the opener working. Every caller, the CLI's openers included, runs `deliverEnded` (`src/local/wakeup.ts`) after commit: it unlinks the ended IDs' sockets, pokes the wakes and sweeps the bytes of the uploads the end dropped. On a clean exit `grayboard mcp` refuses new tool calls and drains, waits for in-flight calls and the drain, ends, then waits for the wakes, each wait capped at `SHUTDOWN_WAKE_MS`; a failed end is logged. A send racing the end either commits first and is bounced, or reaches the write lock after it and is refused `id_ended` (`assertDeliverableId`, inside the send's transaction); `tests/integration/ids.test.ts` forces both through `testPause`.
- **Keyed sessions** (`BUS_SESSION_KEY`, `envSessionKey`; #284 decision 3): an orchestrator mints the key, so it knows the child's ID (`idAddress`) before launch. The session lives as long as its **harness**, not its `grayboard mcp` child: `bindings.pid` is the harness (`BUS_HARNESS_PID`, which must name an ancestor of the process or it refuses to start, else the first ancestor `wrapperName()` doesn't classify as a wrapper (a shell or package runner); `harness_rule` records which), `attached_pid` the child. Only a push-mode process resolves a harness: a keyed tools-only process lives by its own pid and never attaches. A child that exits under a live harness detaches; a restart under the same harness re-attaches (waiting out its predecessor's exit, then re-checked inside one transaction) and is the same session, nothing ended or bounced, audited `id.reattached`; its model and effort become the new child's (`BUS_MODEL`/`BUS_EFFORT`, none when unset), audited `id.facts_changed` (`why: reattach`) when they differ (#365), and its `harness_session` the new child's `BUS_HARNESS_SESSION` when set, recorded on `id.reattached`, so its subagents find it after pi's `/new` (#1075). A key whose session has ended, whose child is still alive, or that belongs to another harness is refused `id_collision`, as is a re-attach whose human-ness doesn't match the held alias (an agent to a session holding the human handle, or `BUS_HUMAN=1` to one that doesn't). An explicit `BUS_IDENTITY` is ignored on re-attach: the session keeps what it held. Keyed sessions write no name record (below): re-attaching is their continuity.
- **`binding_events`** (core schema, `src/core/schema.ts`; written by `logBinding` in both modes, and directly by the hosted store when an ownership ends, `src/server/db.ts`): `bound`, `released`, `refused`, keyed by session ID, with the holder on a refusal. No mode writes `moved` now; older rows carry it from a pre-multi-hold hosted rebind, so readers keep it in their `IN` lists. A refusal joins the session's latest row for the name when that row is a `refused` with the same detail, last repeated within `REFUSED_COALESCE_MS`: its `count` and `last_at` grow instead of a row being added (#210), so a steady retry loop is one row and any other event starts a new one. Retention goes by `last_at` when set. The audit trail for every name change, and the join between run metadata and a name (#185). Retention prunes them with posts (`prunePosts`, `src/core/boards.ts`), except each name's latest `bound`/`moved` event, which says who holds the name by the record (#211).
- **Local names follow the selected conversation** (#195; `src/local/binding.ts:conversationSnapshot`, `src/local/mcp.ts`). Restore the latest ended ordinary root in the current bus by `started_at DESC, rowid DESC`, including `[]`. Snapshot existence is authoritative: no older snapshot, outgoing PID carry or explicit identity fallback after an empty snapshot or refused acquisitions. Restore ordered holds with `create:false`, bounded by `MAX_HOLDS`; a live owner is never displaced. Continuity stays `acquireName`'s transaction-time check, and status is inherited after a verified acquire (`inheritStatus`, #211). Only absent conversation state permits the existing PID record/configured identity precedence. PID records remain same-process carry/restart hints, not a second conversation store. `ids.local_resume` records ordinary local provenance at registration: humans, runners (including fallback/promotion), keyed, viewer and tools-only roots stay excluded while `harness_session` remains available for child-root discovery. Pre-feature rows default excluded; inferential backfill would falsely restore excluded roots. Existing end snapshots and retention are the only persisted name history.
- **Claude's retained local child** (#195; `src/shared/claude_agents.ts`, `src/shared/claude_identity.ts`): the connection environment bootstraps identity but stays stale across `/clear`. SessionStart's payload is authoritative, joined by the harness pid; PreToolUse cross-checks the call's conversation. SessionEnd(clear) waits for every retained child's pause; SessionStart atomically publishes current identity and waits for rotation before returning guidance or a title. Publication failure is visible and cannot release a pause using the outgoing record. Control records are bounded regular files, opened without following symlinks or blocking on FIFOs, with validated fields and socket names confined to the owned base. Dead endpoints and dead PID directories reap only validated generated sockets, never unrelated regular files, symlinks or external paths.

- The local MCP server exits when its client closes stdin; otherwise the socket listener keeps an orphan alive that locks its handle out.

- **Claude Code titles must name an effective hold, never a configured fallback.** The single authoritative SessionStart hook emits title and guidance only after rotation acknowledges (`src/cli/main.ts`, `src/cli/claude_hooks.ts`). A read-only selected-conversation lookup (`src/local/open.ts:readConversationTitle`) suppresses configured titling for ended snapshots, including empty/refused restoration, and uses an active selected root's acquired primary when known. Only absent selected state with no conflicting PID carry permits the configured-new title. It never creates, migrates or reaps the bus, or persists another name store. Title events remain startup/resume/fork, not clear/compact; later binds still do not retitle (#180). This avoids advertising a name peers cannot DM, regardless of hook/MCP startup order. An explicit name visible only in MCP registration's env remains invisible to the hook. Title lookup failure suppresses the title; authoritative publication/rotation failure instead fails the lifecycle hook visibly.
