## 1. Transport and wire

`sdk/rust/grayboard` is a second client of this contract, for services rather than harnesses: modern protocol only, raw JSON-RPC over HTTP (not `rmcp`, whose client would need a custom transport for the per-request lease header, the re-read bearer and the 429 rule). hosted-core's wire is its reference: `scripts/record_rust_fixtures.ts` records the requests `wire.ts` sends for each operation the crate implements into `sdk/rust/schema/wire/requests.json`, the Rust test `requests_match_the_reference_clients_recording` compares the crate's own requests to it, and `tests/integration/rust_fixtures.test.ts` re-records under `bun test` and fails on drift, so an MCP SDK bump that moves the envelope fails without cargo (the fixture found that a notification carries no `Mcp-Method`). Its transport rules follow `wire.ts`: a body-driven 429 (`rate_limited`) retries, up to 8 attempts with the token re-read, and a 401 retries once after the credential replaces its token; nothing else retries. A plain-text 429 is capacity. A `tools/call` that times out or loses its connection after its connect is `OutcomeUnknown`, never retried, since a repeated write doubles; so is a 502, 503 or 504 answering one, since a gateway can answer after the server acted (a read gets `Unreachable`). The connect timeout (5 s) is shorter than the request timeout (10 s), so a blackholed endpoint is `Unreachable`, and the request timeout also bounds the credential's own calls. Refusal codes, suggested names and a holder are kept only when well-formed, as `wire.ts` `subscriberError` keeps them. A dropped `Session` only cancels its requests, its delivery stream's included, so nothing releases the lease; the server keeps the session, and its names, until the lease lapses (30 s) or, with no lease, the idle sweep. A listen stream has an ack timeout and a 15 s idle timeout (three missed keepalives), never a total-body timeout, and never reconnects on its own. Cargo isn't in the root suite or the pre-push hook: `scripts/e2e.sh rust-sdk` runs fmt, clippy, the crate's tests against a scripted endpoint, and `examples/roundtrip.rs` against an in-process server with an operator client (`sessionSource: true`) and a seeded token (`tests/integration/rust_sdk.test.ts`).

## 2. The delivery stream

`Session::deliveries()` (`sdk/rust/grayboard/src/delivery.rs`) ports the lease protocol of `Controller.run` (`adapters/hosted-core/src/controller.ts`) as one spawned task per stream, feeding a one-slot channel; the harness-host parts (approval, guard, drift, rotation grace, children, diagnostics) aren't ported. A change to `controller.ts`'s delivery rules must name its Rust counterpart: only `delivery_tests.rs` (a test per rule below, against a stateful scripted bus) and the example catch drift. Differences from the controller follow from handing items to a caller instead of admitting them inline:
- One item is out at a time, the next only after its `receipt()` lands, since the server receipts direct items only as an in-order prefix of unread; so the in-process dedup state is that one item, not a 100-key set.
- The lease renews in the background while the caller holds an item; the controller has no renew between admission and receipt (#845).
- A `Delivery` dropped without `receipt()` is a failed acceptance (a failure, and the item is shown again).
- Lease losses count with an item out too (the controller exempts losses inside an item, whose admission is brief), so a lease that never comes back can't keep a held item reopening forever.
- `stable_id` hashes no issuer: `delivery_open` returns none, and an endpoint has one.

The subscriber connection outlives leases, so the task clears `X-Grayboard-Lease` before every `whoami`, `bind` and `delivery_open`, and closes each lease's listen stream (its `notifications/cancelled`) before anything that follows: one sent after `session_end` would start a new session under the same ID. `delivery_release` ends the session on the server (`store.end`), so every release (a dropped stream, `end()`, `receipt_capacity` recovery) is followed, if delivery goes on, by rebinding the remembered holds with `create: false`; a second stream on the same `Session` starts after the dropped one's release. The bind rule lives in `call_raw`: `bind`/`unbind` pause the stream, run, refresh the remembered holds from the subscriber `whoami` (after every `bind`/`unbind`, stream or not, since a later stream rebinds them), and resume; an `unbound: true` or alias-lost result on another call restarts it, though not while a bind holds it paused. Unbinding the last hold idles the stream until the next `bind`, giving up a held item; a dropped `Session` ends an idle stream.

| Rule | Reference |
|---|---|
| Open: `whoami`; if nothing is held, bind the remembered holds with `create: false`; if holds differ from the remembered ones, stop (`holds_changed`); an invalid `whoami` (a child session) stops at once | `controller.ts` open, `model.ts` `bindingOf` |
| `whoami` reports `alias_lost`: drop those holds; if none remain, stop (`alias_lost`) | `controller.ts` |
| `delivery_open`: validate `capability` (43 url-safe chars), `ownership`, `bind_gen`, `expiresAt`, an identity naming the first hold (another identity reopens once, then stops: `identity`); send the capability as `X-Grayboard-Lease` | `model.ts` `leaseOf` |
| Listen on `grayboard://inbox`, required in the honored filter; a hint only marks the inbox dirty; the first read is unconditional; a full page (100) means read again; no client cursor | `wire.ts`, `controller.ts` |
| Per item: check `ownership`/`bind_gen`/`address` against the lease (`identity`), `delivery_renew`, hand over, renew every interval until `receipt()`, then `delivery_receipt({ ids: [id] })` | `controller.ts` |
| After a reopen, an item out keeps its handle under the same `ownership:bind_gen:id` key once the new lease's read shows it, and an accepted one goes straight to its receipt; under another key, or not on a full page, the handle is `DeliveryLost` and the item comes again; absent from a short page, its receipt landed | `controller.ts` |
| `stable_id`: `msg_` + SHA-256 of `[1, principal, resource (the endpoint), address or null, item ID, session ID]` | `model.ts` `stableID` (v4, with issuer) |
| Renew every 10 s (TTL 30 s, `src/server/hosted.ts`); an idle renew re-reads the inbox; a healthy renew resets the loss and outage counts | `controller.ts` |
| Stream closed or unreachable: reopen from `whoami`, backoff `min(8 s, 250 ms * 2^n)`, no limit | `controller.ts` |
| Lease lost (`not_found`/`unbound` on `delivery_open`, `delivery_*` or an inbox read): reopen; a fourth loss without a healthy renew stops (`lease_lost`) | `wire.ts`, `controller.ts` |
| An item shown a ninth time (hand-overs and reconfirmations), or 8 other failures in a row: stop (`retry_exhausted`, naming the item) | `controller.ts` |
| `alias_held`, `identity_unknown`, credential and scope errors: stop at once with that error | `controller.ts` |
| `receipt_capacity`: `delivery_release`, then reopen (server side: `src/server/mcp-resources.test.ts`) | `controller.ts` |
| Admission-throttled reopen: wait `max(retry_after_ms, min(8 s, 500 ms * 2^n))`, 8 tries of the transport's own 8 attempts, then the transport's `RateLimited` | `controller.ts` |
| Close (`end()`, or the stream dropped): `delivery_release`, then (`end()`) `session_end` | `controller.ts` |

A stop is one terminal `Err` before the stream ends, delivered even through a pause or restart while the channel is full. A delivery receipt is not `dm_ack`. Renew interval and backoff units are `Timeouts` fields. The example (`examples/roundtrip.rs`) is a queue worker: bind, `board_subscribe` push, take a work item and a DM from the stream, receipt both, reply in the item's thread, `dm_ack` the DM, end; `tests/integration/rust_sdk.test.ts` posts only once the Rust session is subscribed with an open lease, then asserts on server state.
