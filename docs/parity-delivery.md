## 1. Tool surface

- Local (all four): the tools `grayboard mcp` serves (`src/core/tools.ts`, `src/local/mcp.ts`); the child adapters register `grayboard tools`' list under the names each harness showed before (adapters.md). Proof: `tests/integration/pi.test.ts` piScenario (the request's tool list equals the served one), `tests/integration/opencode.test.ts` ("every tool `grayboard tools` lists converts to zod"), `tests/integration/local.test.ts` ("the reply and recovery tools ask Claude Code to load them upfront").
- pi H, omp H, CC H: hosted-core's proxy of the server's native tools, with paths on `dm_send`/`board_post` and a local `attachment_get` added (`hostTools`, `adapters/hosted-core/src/proxy.ts`). OC V2: the native tools as served, with paths on `dm_send`/`board_post` and an `attachment_get` the package adds (#578, `adapters/opencode-v2/README.md` §Attachments). Proof: `tests/integration/hosted_core_snapshot.test.ts` (the snapshot equals the live native `tools/list`).

## 2. Push delivery and wakeup

- pi L, omp L, OC V1: DMs, mentions and thread replies start a turn; digests and deferred pushes are context only (adapters.md). Proof: `tests/integration/pi.test.ts` piScenario, `tests/integration/omp.test.ts` omp local task run (a peer's DM reaches main once), `tests/integration/opencode.test.ts` ("an unbound session acts as its ID…": the DM arrives as a prompt).
- CC L: channel notifications, only while Claude Code's channel gate registers the server; gate off → tools-only, reason in instructions and first result (`claudeChannels`, adapters.md). Proof: `tests/integration/local.test.ts` (pushes at the MCP level; "a Claude Code session whose channels are off runs tools-only and is warned why").
- pi H, omp H, CC H: hosted-core lease and `RootDelivery` (adapters-hosted.md §Hosted core). CC H's lease is `context: false`, so a digest or deferred push waits for a waking item instead of starting a turn (#854). Proof: `tests/integration/pi.test.ts` "pi hosted: …", `tests/integration/omp.test.ts` "omp hosted: …", `tests/integration/claude_plugin.test.ts` ("a flagged interactive session: … a DM arrives as one channel push"), e2e `claude-hosted` (`tests/e2e/claude_hosted.e2e.ts`).
- OC V2: delivery opens only on a human-enrolled, bound root (#226; `docs/guide/harnesses.md` §OpenCode V2). Proof: `adapters/opencode-v2` `test:host` (`adapters/opencode-v2/tests/host.ts`).

## 3. Current instructions on push-started turns

- pi L, pi H: pi runs `before_agent_start` for a push-started turn, so its `<grayboard>` section is current (`adapters/pi/grayboard.ts`, `adapters/pi-family/entry-pi.ts`). Proof: `tests/integration/pi.test.ts` piUnboundScenario (a woken turn's system prompt is the bound name's), piHostedScenario.
- omp L, omp H: one shared plan (`adapters/pi-family/omp-instructions.ts`, #441, #552): `before_provider_request` rewrites stale instructions per request, `context` adds them as a hidden message after a prompt rebuild, and both warn once for main only when the stale text can't be found. omp L reads the current text from its child's last initialize; omp H fetches it. Proof: `tests/integration/omp_instructions.test.ts` (plan, rewrite and the warning), `tests/integration/omp.test.ts` omp local ("a push-started bind reaches the next request's instructions without a user prompt") and omp hosted `/fork`, `/new`, `/resume`.
- OC V1: `experimental.chat.system.transform` adds the latest instructions to every request (`adapters/opencode/grayboard.ts`). Proof: `tests/integration/opencode.test.ts` ("… the system prompt follows in full").
- OC V2: the plugin's `context` hook carries the root's (or a subagent's child) server instructions per request (#531, #535). Proof: `adapters/opencode-v2/tests/host.ts` (REAL_INSTRUCTIONS cases), `adapters/opencode-v2/tests/instructions.test.ts`.
- CC L, CC H: Claude Code retains connect-time MCP text in its system/transcript context; bind/unbind results carry rebuilt instructions, or the next result after a lost one (`instructionsStale`, `src/local/mcp.ts`). CC L also publishes current root ID/holds as native guidance before pending delivery after restored/changed conversation identity, superseding the saved transcript's stale bus instructions. Proof for CC L fresh resume: `tests/e2e/local_resume.e2e.ts` checks the actual pushed model request's current root and ordered holds; CC H: —.

## 5. Names across an in-process session switch or MCP reconnect

- pi L, omp L, OC V1, CC L: selected-conversation state wins, including an authoritative empty hold set. Only absent remembered state permits outgoing carry for `/new`, fork or switch; a same-ID MCP reconnect restores that conversation rather than another conversation's PID names (sessions.md, adapters.md; #195). pi restarts its child; omp, OC V1 and Claude Code retain it while rotating the bus root. Owner/epoch or authoritative hook barriers settle delivery and apply incoming instructions before tools/pushes resume. Proof: `tests/integration/local_resume.test.ts` plus each real harness's lifecycle coverage.
- pi H, omp H: `/new` and fork carry the outgoing root's holds; pi `/reload` keeps the lease (adapters-hosted.md §Hosted pi, §Hosted omp). Proof: `tests/integration/pi.test.ts` piHostedCarryScenario, `tests/integration/pi_family.test.ts` (`/new` carry, reload detach), `tests/integration/omp.test.ts` omp hosted `/fork`, `/new`, `/resume`.
- CC H: the lease is keyed by `CLAUDE_CODE_SESSION_ID`, which survives `/clear` (adapters-hosted.md). Proof: e2e `claude-hosted` (the facts test's root continues across `/clear`).
- OC V2: n/a. Each OpenCode session is its own root that a human enrolls (#226); nothing carries between roots by design, and the `name` option binds each new root.

## 6. Names when a new harness process resumes a conversation

- pi L, omp L, OC V1, CC L: the latest ended ordinary root snapshot for the selected conversation restores ordered holds with `create:false`, before PID carry or configured identity. `[]` is authoritative; refusal never falls through to older state or steals a live name. Existing open/reap handles a crash before selection. Proof: `tests/integration/local_resume.test.ts` and actual pinned `tests/e2e/local_resume.e2e.ts` (`scripts/e2e.sh local-resume`): all four launch genuinely new processes on their saved session/store, restore renamed multiholds, receive queued pushes with current guidance, and remain unbound after final unbind and another fresh resume. Claude Code's measured post-tools-list-response ping barrier precedes native guidance/mail; it is activation evidence, not a native delivery receipt.
- pi H, omp H, CC H: a root's start takes back its `rememberedHeld` holds with `create:false` before `BUS_IDENTITY` (`RootDelivery.begin`, `adapters/hosted-core/src/root.ts`; `claude --resume <id>`, adapters-hosted.md). Proof: `tests/integration/hosted_core_root.test.ts` ("a resumed session takes back what it held"), `tests/integration/pi_family.test.ts` ("… a later resume rebinds the remembered name"). A start during a server outage retries that resume on the outage backoff rather than leaving the root dark (#895; `adapters/hosted-core/tests/controller.test.ts` "a resume during a server outage retries…").
- OC V2: the plugin persists the bound name and rebinds it on resume (#251), and a reload during an access-expiry wait restores the root into that wait, which a later refresh resumes (#661; `adapters/hosted-core/tests/controller.test.ts` "a reload during the wait…"). A host that restarts during a server outage retries each saved root on the outage backoff rather than pausing it (#424 6; pi H, omp H, CC H: #895, above); a token that expired during an outage makes the run loop's or the restore's retry ask OpenCode to refresh it once the server answers (#916; "a native token that expires during an outage asks OpenCode to refresh…"). Proof of the retry: `adapters/opencode-v2/tests/controller.test.ts` ("a restore during a server outage retries…"). Proof: `adapters/opencode-v2` `test:host` (crosses a host process reload, `adapters/opencode-v2/README.md`).

## 7. Automatic restart after the grayboard process exits

- omp L: an unexpected exit restarts the process after 0, 1 and 5 s (a run of 60 s resets the count); the selected conversation's latest snapshot restores names, with PID carry only when no snapshot exists (row 6; `RESTART_DELAYS_MS`, `adapters/omp/grayboard.ts`); a live child that hit EPIPE is killed, and its exit awaited (SIGKILL after 1.5 s, logged), before its replacement starts, which takes the name back (#580); quit awaits that exit too, and a child still running 1.5 s after quit closes its stdin gets SIGTERM, then SIGKILL 0.4 s later, inside omp's 2 s handler cap (#604). A tool call waiting for the process (a transition, a pending restart, initialization) stops waiting when aborted, as pi L's does (#559); omp stops awaiting its hooks at an abort. A child that hasn't answered initialize and finished its session handshake within 30 s is killed and restarted as an exit is, so a wedged child ends in the same give-up (#559). Bun 1.4.4 silently accepts small writes to closed stdin, so those calls can wait until cancellation or child exit. Proof: `tests/integration/omp.test.ts` omp local ("a killed grayboard process is restarted and takes its name back", "a tool call waiting out a restart's 5 s backoff ends at its abort…", "a grayboard process that never answers initialize is killed at the deadline…", "a grayboard that stops reading while it holds the name is killed on EPIPE…", "one that also ignores SIGTERM is SIGKILLed, logged…").
- pi L: the same policy as omp L (0, 1 and 5 s; a 60 s run resets the count; one more exit gives up and says so); calls during a pending restart wait for it and honor their abort, `/new` and shutdown cancel it, and a live child that hit EPIPE is killed, and its exit awaited (SIGKILL after 1.5 s, reported; shutdown awaits it too), before its replacement starts, which takes the name back (`adapters/pi/grayboard.ts`, #559, #599); the same 30 s initialization deadline as omp L; a child still running 3 s after shutdown closes its stdin gets the same SIGTERM, SIGKILL and await (#604). Proof: `tests/integration/pi.test.ts` ("pi local: a killed grayboard restarts with its bound name…", "/new during a pending 5 s restart…", "/new aborts a tool awaiting the pending restart…", "pi local: a grayboard process that never answers initialize is killed at the deadline…", "pi local: a grayboard that stops reading while it holds the name is killed on EPIPE…", "pi local: one that also ignores SIGTERM is SIGKILLed, reported…").
- OC V1: the same policy as omp L (0, 1 and 5 s; a 60 s run resets the count; one more exit gives up and says so); calls during a pending restart or initialization wait for it and honor their abort, a session switch or shutdown cancels a pending restart, and a live child that hit EPIPE is killed before its replacement (`adapters/opencode/grayboard.ts`, #576); the same 30 s initialization deadline as omp L (#559). Bun 1.4.4 silently accepts small writes to closed stdin, so those calls can wait until cancellation or child exit; the EPIPE proof uses a large write. Proof: `tests/integration/opencode.test.ts` ("opencode real: child restarts restore held names, tool calls and delivery, then exhaust", "opencode real: switch during backoff cancels the outgoing restart without an orphan", "opencode real: shutdown during backoff cancels the outgoing restart without an orphan", "opencode: aborting a tool during backoff releases its wait promptly; shutdown also releases waiting calls", "opencode: a child stable for 60 seconds resets the consecutive restart count", "opencode: Bun EPIPE waits for the still-live owner to die before retrying and exhaustion leaves none", "opencode: aborting a tool blocked in initialize does not wait for the child's paused bind", "opencode: a grayboard process that never answers initialize is killed at the deadline…").
- CC L: n/a. Claude Code's own MCP client runs `grayboard mcp`; no grayboard component exists to restart it. Recovery is `/mcp reconnect`, which takes the names back (row 5).
- pi H, omp H, OC V2: n/a. No grayboard process: the extension or package runs inside the harness and talks to the server over HTTP.
- CC H: n/a. The plugin is Claude Code's stdio MCP server, so its process lifecycle is Claude Code's; a restarted plugin takes back the session's remembered holds (row 6).

## 8. Subagents as child sessions, writes attributed (`via`)

- pi L: pi-subagents' detached runner is a child of its parent session and can promote itself by binding (child-sessions.md §Local runner children). In-process foreground children load no ambient extensions; one that names the grayboard extension explicitly is its root's child the same way, found by its session header's `parentSession`, when the launching session has a session file (#557). A keyed root's subagents are its children with or without a header; a human root's get no session and say why (#1075). Proof: `tests/integration/pi.test.ts` piRunnerScenario, piForegroundChildScenario, piExcludedForegroundChildScenario.
- omp L: a `kind: "sub"` runtime's call carries its agent id under `GRAYBOARD_AGENT_META`; subagents get no pushes and no instructions (#523, #526). Proof: `tests/integration/omp.test.ts` omp local task run.
- OC V1: sessions with `parentID` send their session id under `GRAYBOARD_AGENT_META`, using local MCP's existing `ChildSessions` path; bind and unbind remain the root's. The system transform renders child-only instructions from a child-scoped `whoami`, never the root's instructions (#577). Children get no pushes and end with the local root, as omp's do. Proof: `tests/integration/opencode.test.ts` against pinned OpenCode 1.19.4 ("opencode real: subagent writes via its root, cannot bind, and gets child instructions"), plus SDK lookup coverage for resumed nested children before a creation event.
- pi H, omp H: a child registers under its root before its first call (adapters-hosted.md §Hosted pi, §Hosted omp). Proof: `tests/integration/pi_family.test.ts` ("a marked child registers under its root…"), `tests/integration/omp.test.ts` omp hosted task run.
- OC V2: every subagent of an enrolled root registers as a child and gets the server's child instructions (#535). Proof: `adapters/opencode-v2/tests/host.ts` (REAL_INSTRUCTIONS_SUBAGENT_OK), `adapters/opencode-v2/tests/instructions.test.ts`.
- CC L, CC H: hooks write a per-call agent record that the MCP side takes; a call with no record is refused, never run as the root (#551; child-sessions.md §Claude Code children). CC H's child is `<session id>/agent/<agent id>`, ended by `SubagentStop` (`plugins/claude-code/src/plugin.ts`). Proof: e2e `claude-local` (`tests/e2e/claude_local.e2e.ts`), `tests/integration/claude_records.test.ts`, `tests/integration/claude_plugin.test.ts` ("a subagent's call runs as a child of the root, with via", "a plugin restarted after a subagent's call still ends that child's session…").
