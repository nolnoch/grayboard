# Claims

```doc-meta
owns: claims: take, renew, release, expiry, watches, history, board announcements, the claim CLI
invariants: claims are atomic, expiring, and enforced state; a claim stays with the address it was taken under; renewal never shortens by default; release and expiry delete the row, `claim_events` keeps the history
code-pointers: src/core/claims.ts, src/core/boards.ts (queue claims), src/cli/claims.ts, src/cli/claim.ts
companions: boards.md (queue boards, board posts), handles.md (addresses), server-access.md (claims are org-wide)
```

- `claim_take(key, ttl_minutes? | until?, note?, board?)`: take, renew (if you hold it), or learn who holds it. `claim_release(key, note?)`: holder only; the note rides on the release post (not on one written for the claimant's user, under Watches).
- **A repeated release answers from state** (#254): when the key's latest `claim_events` row is the caller's release (or, on a `queue:` key, the redelivery take that release made directly after it), the call succeeds with `already released by you at T`, writing no second event and redelivering nothing. Checked inside the release transaction, only where the release would otherwise refuse. Anything since (someone took it, released it, or a TTL takeover) and today's errors stand: a fingerprint would wrongly replay "released" after an intervening take.
- **Renewal never shortens by default**: without `ttl_minutes`/`until` it keeps the later of the current expiry and now+default. Resetting to now+default silently cut multi-day claims to the default TTL when an agent renewed only to change the note (#37). An explicit ttl or `until` still sets the expiry, shorter or not.
- **Progress updates** ride on renewal, not a separate tool: a renewal whose given note differs from the current one posts `[update] key — note` on the claim's board, mentioning watchers without consuming them. An unchanged note is silent, as is an update by a holder who lost the board.
- **A renewal naming another `board` moves the claim there**, and refuses, rolling the renewal back, when that board is archived (#635) or the claim's holder can't see it (#1269). The second matters for a caller with several addresses: a renewal keeps the address the claim was taken under, so the caller's own sight of the board isn't enough; a renewal never puts a claim on a board its holder can't read.
- **Atomic**: one `INSERT … ON CONFLICT` transaction; two agents can't both win.
- **Expiring**: TTL (default and max in `src/core/claims.ts`) or explicit `until`, stored as an absolute timestamp so it survives restarts. Expired claims are free; a crashed agent's claims lapse on their own. An alias's claims don't release when a session exits: agents resume work across restarts under the name. Claims held by a session ID are released when that session ends (`sessions.md`).
- **A team's holder is the team's** (#871): to a reader outside the team (`alias.see`, `handles.md` §Presence), a claim a team alias holds is listed and still refuses a take, but with `holder` and `note` null (`claim_list`, `board_read`'s `active_claims`, `claim_take`'s `held_by`, HTTP `/api/claims`, which `grayboard claims` prints as held by someone you can't see), and `claim_release`/`claim_watch` errors don't name it. A team name deleted while it holds a claim (`team delete-alias`) stays the team's. On a queue board, a mention of such an alias routes as a name nobody has: a lane still gets the post and its queue claim. Dropping the row instead would hide nothing, since the key is one namespace and a take is refused anyway. Local mode lists every holder.
- **A hidden board's claim keeps its room's words** (#1257): to a reader who can't see the claim's board (a team's or a service's), `claim_list` lists the claim with `board` and `note` null, and HTTP `/api/claims` (which never names boards) and `claim_take`'s held answer with `note` null, since the note was written for that board. That holds even for the claim's own holder once it can no longer see the board (say, removed from the team); its session-start notice and a renewal's answer still carry the note. The holder field follows the rule above. A queue post's claim on such a board isn't listed at all (`server-services.md` §2).
- Keys are free-form by convention (`ticket:ENG-142`, `path:src/foo/`, `lane:fixtures`); grayboard doesn't know what a ticket is.
- **Board announcements**: claim, update, release and expiry post to `board`. One timer per live session (local) or the server, armed for the next expiry and re-armed after tool calls and wakeups. The sweep deletes and posts in one transaction, so a lapse posts once. Taking over a lapsed claim announces the lapse first. An expiry post says nobody confirmed the work was done. A key or note with a NUL is refused at the take or release (`validKey`, `validNote`), and an announcement carries any NUL a row from before that refusal holds as U+FFFD (`systemBody`, `src/core/boards.ts`; core's `announce`/`requeue`, the server's `systemPost`): a refused announcement would make every sweep throw, so every later take, on any key, would fail. An announcement a session's call makes is that session's post (`author_id`), so it isn't pushed to any of the session's other names (`boards.md` §4); a sweep's post has no writing session and excludes only its author. On a server every announcement records the claimant's user as its writer (`author_user`, #855): a call's from the caller, and a post with no signed-in caller (a sweep's expiry, a session end's release) from `claims.holder_user`, set at take and renewal, or for a claim taken before that column (or a queue delivery to an alias no session held then) an ID holder's principal, else the user of the session holding the alias at the post, else a person alias's person. So `msg.wake` (`server-access.md` §1) marks it for another user's agent exactly as the holder's own posts; `holder_user` never reaches a claim's reader (`CLAIM_COLS`).
- **`queue:` keys are queue-board deliveries** (`boards.md` §3), minted only by `claimQueuePost` (`src/core/boards.ts`); `claim_take` refuses the prefix, since a squatted key would audit a delivery that never happened and break the lane's reply-ack. They don't announce on the board as other keys do (an announcement there would rotate as a new work item): a take is the push (a mention's claim, #219: the mention is), and a holder's thread reply releases with note `ack` (`ackQueueClaim`; `ack (late)` when the row lapsed but the sweep hadn't reached it, which then redelivers nothing). A release or lapse redelivers the post to a lane that hasn't held it (`redeliverQueuePost`; one turn per lane, #220, `boards.md` §3) and consumes watches quietly; with no lane left, the claim's end is a `[unclaimed]` reply in the post's thread, written as the last holder (a decline's as the declining session, `author_id`, and on a server as the caller's user; a lapse's as `claims.holder_user`, the lane's session's user at delivery, else the user of the session holding the lane's alias at the lapse; a team alias nobody holds then names no user), which `@mention`s the watchers. A last holder that lost the board ends it by the same reach rule as a release or lapse (below, #1296). When that rule finds no one, the last holder is a declared human (a claim from before humans left the lanes, #1175, or a handle declared human after its take), or the reply is refused, the post's own author writes it (`requeue`, `src/core/claims.ts` and `src/server/claims.ts`), as the post's writer (its `author_id` and `author_user`): it's the reader the reply informs, its address set never wakes on it (post's own-exclusion, so an author that watched its own post gets the reply on its next read, not a push, though the text still mentions it), and the watchers are told as from a holder. Only when the author can't see the board either, or is a declared human, is the end quiet: system text never bears the human mark (`slack-bridge.md` §3), so the reply is never written as one. Only a take whose row wins is logged.
- No veto windows, no queues: held or not, and who holds it. Advisory to the world (grayboard can't stop a file edit), truthful to any agent that asks.
- **Watches** (`claim_watch`, `claim_watches` table): the `[update]` post and the end post (release, expiry, or a queue post's `[unclaimed]` reply) `@mention` watchers, so they reach them in any subscription mode and survive `/clear`. Mention resolution already drops anyone who can't see the board; `watch()` refuses up front a claim with no board or one the watcher can't see, since its end post couldn't reach them. The end post consumes the watches (`takeClaimWatchers`), so a later claim on the key starts with none; so does a quiet end. A holder that lost the board (on a server, an ID whose primary moved to another team's name, #1255) ends its claim, by release or lapse (a queue post's `[unclaimed]` reply included, #1296), for the claimant's user when that user still sees the board (`endReachRule`, `src/core/claims.ts`, #1286), so watchers keep their end post (principle 3): written as the holder with `author_user` the claimant's user (#855) and no `author_id`, its gate passed on the user's sight (`PostOpts.seenBy`, set only from the claim row), in fixed text that never carries the caller's note (a session end's included), so a confined holder's words can't reach a board outside its team; the caller's answer and deliveries are a quiet end's, and no invocation is recorded for it. When neither sees the board, the end is quiet, but for a queue post's `[unclaimed]` reply, which its author writes (above, #1175). Local mode never takes that path (`Access.userSees` is unset).
- Active claims are listed in each session's instructions at start, so a fresh or `/clear`-ed session sees them without knowing to look. Claude Code truncates long server instructions (limit noted at `MAX_CLAIMS_CHARS`, `src/core/tools.ts`), so `claimsInstruction` lists the session's own first (notes clipped), others as bare keys within a char budget, then "N more", and both modes put it last so a cut takes it rather than fixed text. Others' are keys only: every call pays for the text, and `claim_take` refuses a held key with its holder. The keys stay because a signal like `dev:freeze` is never `claim_take`n, so a refusal can't reveal it.
- **History** (`claim_events`): release and expiry delete the `claims` row, so each take, renew, refused take (with `held_by`), release and expiry also appends an event in the same transaction; rows from before 2.0 may also say `moved` (a hosted rebind carried the claim; `held_by` the old name). `session_id` is the session holding the handle when the row was written (null for an alias no session held, and for rows from before #1351). It exists for usage analysis (`scripts/usage.ts`); runtime reads are a repeated release's check (`releasedByRule`, `src/core/claims.ts`), a queue post's one turn per lane (`redeliverQueuePost` skips every lane of a session that has a `take` on the key: the row's `session_id` while that session is live, else whoever holds its handle now, #220, #1174, #1351; a key's events are never older than its post, so pruning them with posts keeps the rule while the post exists) and a queue board's rotation order (each lane's latest queue `take`, by the same session rule, `queueLanes`, `src/core/boards.ts`; #221, #1174). Retention prunes it with posts, in both modes (`src/server/retention.ts`, `src/local/retention.ts`).
- `grayboard claims` (`src/cli/claims.ts`) has exit codes chosen for harness hooks: a match blocks, its own errors fail open (`docs/guide/local.md` §Boards and claims, "Guarding a merge or deploy with a hook").
- `grayboard claim take|release|watch` (`src/cli/claim.ts`) runs the claim tools from a shell as the handle `grayboard mcp` would resolve in that directory (or `--as`, taken literally: no worktree suffix), so a script's claim is held by that directory's session. Local mode calls the core directly and pokes the wake list plus the acting handle, whose wakeup re-arms its claim-expiry timer as its own tool call would. It refuses a handle that has never connected, so a typo can't hold a claim no session answers for, and the human handle (`slack-bridge.md` §3; on a server, the reserved name `human`, `slack-org-bridge.md`). `isHuman` must run before the `lastSeen` check: `declareHuman` touches the handle, so a declared human that never connected passes `lastSeen`. Server route: `server-access.md` §1.
